# Блок: Питание

Версия: 1.0 (Концепция)

==========================================
1. ОСНОВНАЯ ИДЕЯ (ОБЯЗАТЕЛЬНО)
==========================================

Раздел "Питание" предназначен не для подсчета продуктов, а для хранения, анализа и контроля питания пользователя.

Stubborn Ram не заменяет FatSecret, Yazio и другие приложения.

Пользователь может использовать любой удобный способ ведения питания.

Система лишь получает, хранит, анализирует и предоставляет эти данные пользователю и тренеру.

Все данные принадлежат пользователю.

==========================================
2. ГЛАВНЫЙ ПРИНЦИП (ОБЯЗАТЕЛЬНО)
==========================================

В основе раздела лежит принцип:

ПЛАН ↔ ФАКТ

Пользователь всегда одновременно видит:

• назначенный план питания;
• фактические показатели за выбранный день.

Например

Калории

3057 / 3000

Белки

182 / 180

Жиры

58 / 60

Углеводы

392 / 400

Вода

2.8 / 3.5

Пользователь никогда не видит только фактические значения.

Он всегда видит их относительно назначенного плана.

==========================================
3. СТРУКТУРА ЭКРАНА (ОБЯЗАТЕЛЬНО)
==========================================

Экран питания строится сверху вниз следующим образом.

1. Календарь

Отображается неделя с выбранной датой.

При выборе любой даты открывается именно этот день.

Интерфейс всегда остается одинаковым независимо от выбранной даты.

Не существует отдельных разделов:

• Сегодня
• История

Существует единый экран "День питания".

2. Цель периода

Под календарем отображается текущий этап питания.

Например:

• Массанабор до 30 апреля
• Снижение веса
• Восстановление
• Подготовка к соревнованиям

Рядом располагается кнопка "Подробнее".

При открытии отображается:

• описание текущего периода;
• задачи периода;
• рекомендации;
• комментарии;
• дополнительные пояснения.

Данный блок описывает весь текущий этап подготовки.

==========================================
4. ПЛАН НА СЕГОДНЯ (ОБЯЗАТЕЛЬНО)
==========================================

Под блоком "Цель периода" может отображаться дополнительная карточка:

План на сегодня

Карточка появляется только тогда, когда для выбранного дня существуют индивидуальные назначения.

Если специальных назначений нет — карточка полностью скрывается.

Она может содержать:

• комментарий тренера;
• комментарий пользователя;
• специальные указания;
• изменение КБЖУ;
• изменение нормы воды;
• читмил;
• рефид;
• загрузку углеводами;
• слив воды;
• любые другие назначения.

Карточка должна визуально выделяться среди остальных элементов интерфейса.

Ее задача — сразу обратить внимание пользователя на сегодняшний день.

==========================================
5. КБЖУ И ВОДА (ОБЯЗАТЕЛЬНО)
==========================================

После блока "План на сегодня" отображаются основные показатели:

• Калории
• Белки
• Жиры
• Углеводы
• Вода

Каждый показатель отображается как:

Факт / План

Например:

3057 / 3000

Для каждого показателя используется цветовая индикация.

Цвет зависит от отклонения относительно плана.

Например:

• зеленый — попадание в допустимый диапазон;
• желтый — небольшое отклонение;
• красный — значительное отклонение.

Конкретные диапазоны допуска определяются позднее.

🧂 ДОПОЛНЕНИЕ: СОЛЬ

Соль является одной из основных метрик питания и работает по той же логике, что и остальные показатели.

Основные показатели питания:
• Калории
• Белки
• Жиры
• Углеводы
• Вода
• Соль

Логика работы:
• Для соли существует план и факт (например: 6 г / 5.8 г).
• Соль может назначаться пользователем самостоятельно или тренером.
• Тренер может изменять количество соли как бессрочно, так и для конкретного дня.
• Соль отображается рядом с остальными показателями и участвует в цветовой индикации выполнения плана.
• Если при импорте данных (FatSecret или AI) информация о соли отсутствует, отображается значение «Не указано», без попыток вычисления.

Архитектурные требования:
• Значение соли сохраняется в истории каждого дня.
• Значение участвует в аналитике питания.
• Значение доступно тренеру при просмотре питания клиента.
• Значение входит в недельные отчеты и экспорт данных.

==========================================
6. ДОБАВЛЕНИЕ ДАННЫХ (ОБЯЗАТЕЛЬНО)
==========================================

Под блоком КБЖУ располагается кнопка:

Добавить данные

После нажатия пользователю предлагается выбрать способ внесения информации.

Поддерживаются три способа.

1. Вручную

Пользователь вводит:

• калории;
• белки;
• жиры;
• углеводы;
• воду.

2. FatSecret

При наличии подключения система получает данные автоматически.

Синхронизация выполняется без необходимости ручного переноса продуктов.

3. Импорт скриншотов (AI)

Пользователь выбирает до четырех скриншотов дневника питания.

Система:

• распознает информацию;
• преобразует изображения в текст;
• показывает результат пользователю;
• после подтверждения сохраняет данные.

После успешной обработки изображения автоматически удаляются.

В системе сохраняется только текстовая информация.

==========================================
7. ХРАНИМЫЕ ДАННЫЕ (ОБЯЗАТЕЛЬНО)
==========================================

Для каждого дня питания сохраняются:

• дата;
• калории;
• белки;
• жиры;
• углеводы;
• вода.

При наличии дополнительной информации также сохраняются:

• список продуктов;
• граммовки;
• приемы пищи.

Также сохраняются:

• источник данных
    • вручную;
    • FatSecret;
    • AI;

• дата и время последнего изменения записи.

==========================================
8. ДАННЫЕ ПИТАНИЯ (ОБЯЗАТЕЛЬНО)
==========================================

Под кнопкой "Добавить данные" располагается раздел:

Данные питания

При открытии отображаются:

• завтрак;
• обед;
• ужин;
• перекусы;
• список продуктов;
• граммовки.

По умолчанию данный раздел свернут и не загружает основной экран.

==========================================
9. РЕДАКТИРОВАНИЕ ДНЕЙ (ОБЯЗАТЕЛЬНО)
==========================================

Любой день питания остается доступным для редактирования.

Пользователь может:

• изменить КБЖУ;
• изменить воду;
• повторно импортировать данные;
• изменить продукты;
• добавить комментарий.

История и сегодняшний день используют абсолютно одинаковый интерфейс.

==========================================
10. ПЛАНЫ ПИТАНИЯ (ОБЯЗАТЕЛЬНО)
==========================================

План питания является самостоятельным объектом системы.

Он содержит:

• автора;
• название периода;
• дату начала;
• дату окончания (необязательно);
• КБЖУ;
• воду;
• описание;
• рекомендации;
• комментарии.

Если дата окончания отсутствует,

план считается действующим до появления следующего плана.

==========================================
11. ИНДИВИДУАЛЬНЫЕ ДНИ (ОБЯЗАТЕЛЬНО)
==========================================

Помимо основного плана можно назначать отдельные изменения для конкретных дат.

Например:

• читмил;
• рефид;
• загрузку углеводами;
• слив воды;
• изменение КБЖУ;
• изменение воды;
• специальные комментарии.

Такие изменения действуют только в выбранный день.

После окончания дня система автоматически возвращается к основному плану периода.

==========================================
12. САМОСТОЯТЕЛЬНЫЙ ПОЛЬЗОВАТЕЛЬ И ТРЕНЕР (ОБЯЗАТЕЛЬНО)
==========================================

Самостоятельный пользователь самостоятельно создает планы питания.

При наличии тренера именно тренер получает право создавать и изменять планы.

Архитектура раздела остается одинаковой.

Меняется только автор плана.

==========================================
13. АРХИТЕКТУРНЫЕ ПРИНЦИПЫ (ОБЯЗАТЕЛЬНО)
==========================================

В системе не существует отдельного объекта:

"Текущий план питания".

Хранятся только планы питания с датой начала действия.

При открытии любого дня система автоматически определяет, какой именно план действовал на выбранную дату.

Это позволяет:

• не дублировать данные;
• полностью сохранять историю;
• корректно строить аналитику;
• видеть реальные планы любого периода спустя годы.

==========================================
14. АНАЛИТИКА (АРХИТЕКТУРНОЕ ТРЕБОВАНИЕ)
==========================================

Все данные питания должны сохраняться таким образом, чтобы в дальнейшем можно было построить раздел аналитики.

Планируется отображение:

• средних калорий;
• среднего белка;
• среднего количества жиров;
• среднего количества углеводов;
• среднего количества воды.

Данные отображаются в виде графиков за выбранный период.

Пользователь сможет:

• включать и отключать отображение отдельных показателей;
• сравнивать различные периоды;
• анализировать динамику питания.

Архитектура хранения данных должна изначально поддерживать подобную аналитику.

==========================================
15. СВЯЗЬ С ДРУГИМИ РАЗДЕЛАМИ (ОБЯЗАТЕЛЬНО)
==========================================

Раздел "Питание" является единым источником данных для:

• аналитики;
• недельных отчетов;
• просмотра тренером;
• формирования обратной связи;
• сравнения периодов.

Никакие данные не копируются.

Все остальные разделы получают доступ к одному и тому же объекту питания.

==========================================
ГЛАВНАЯ ИДЕЯ
==========================================

Раздел "Питание" представляет собой единый центр хранения и анализа питания пользователя.

Пользователь сам выбирает наиболее удобный способ внесения данных:

• вручную;
• через FatSecret;
• с помощью искусственного интеллекта.

Система не заменяет приложения для подсчета калорий, а объединяет всю информацию в единой базе данных, позволяя анализировать питание, сравнивать план с фактом, отслеживать динамику и при необходимости предоставлять доступ тренеру без создания копий данных.
