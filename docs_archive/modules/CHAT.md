СТРУКТУРА РАЗДЕЛА «ЧАТ»
Версия 1.0 (утверждено)
══════════════════════════════════════════════════════════════

1. НАЗНАЧЕНИЕ РАЗДЕЛА

Чат является рабочим пространством общения между тренером и
клиентом.

Он не заменяет Telegram или другие мессенджеры, а дополняет
экосистему Stubborn Ram возможностью обсуждать любые вопросы,
используя данные платформы.

Главная задача чата — максимально быстро обсудить конкретный
объект платформы без поиска его вручную.


══════════════════════════════════════════════════════════════

2. ОБЩИЙ ПРИНЦИП

Существует один чат между одним тренером и одним клиентом.

В чате можно обсуждать любые темы:

• тренировки;
• питание;
• активность;
• вес;
• контрольные точки;
• отчеты;
• любые организационные вопросы.

Дополнительные чаты внутри отдельных разделов не создаются.


══════════════════════════════════════════════════════════════

3. ФУНКЦИОНАЛ ЧАТА

Поддерживаются:

• текстовые сообщения;
• голосовые сообщения;
• фотографии;
• видео;
• документы;
• прикрепление объектов платформы;
• Reply (ответ на конкретное сообщение);
• поиск;
• редактирование сообщений;
• удаление сообщений;
• сохранение черновиков.

Не поддерживаются:

• GIF;
• стикеры;
• реакции;
• каналы;
• истории;
• статусы;
• любые дополнительные функции обычных мессенджеров,
не влияющие на работу тренера и клиента.


══════════════════════════════════════════════════════════════

4. ПРИКРЕПЛЕНИЕ ОБЪЕКТОВ ПЛАТФОРМЫ

Кроме обычных файлов пользователь может выбрать действие:

«Прикрепить объект платформы».

После выбора открывается не отдельный интерфейс,
а существующая структура приложения поверх окна чата.

Пользователь перемещается по разделам точно так же,
как обычно работает внутри приложения.


══════════════════════════════════════════════════════════════

5. РЕЖИМ ВЫБОРА ОБЪЕКТА

После выбора раздела открывается его обычный интерфейс.

До момента выбора конкретного объекта никаких изменений
интерфейса нет.

Когда пользователь доходит до уровня объекта,
который можно прикрепить,
у него появляется небольшой круглый переключатель
для выбора объекта.

После выбора объект отправляется в чат.

Таким образом не создается отдельный интерфейс выбора —
используется уже существующий интерфейс приложения.


══════════════════════════════════════════════════════════════

6. КАКИЕ ОБЪЕКТЫ МОЖНО ПРИКРЕПИТЬ

Прикреплять можно любой самостоятельный объект платформы.

Например:

• тренировку;
• упражнение;
• конкретный подход;
• день питания;
• запись веса;
• контрольную точку;
• фотографию;
• отчет;
• другие самостоятельные объекты платформы.

Разделы верхнего уровня (например «Тренировки»)
не прикрепляются.

Прикрепляются только реальные рабочие объекты.


══════════════════════════════════════════════════════════════

7. ПРИНЦИП КАРТОЧКИ ОБЪЕКТА

После прикрепления объект отображается в виде компактной
карточки.

Карточка содержит только необходимую информацию:

• тип объекта;
• название объекта;
• дату.

Карточка не должна содержать длинных описаний,
чтобы не перегружать переписку.

Вся подробная информация открывается после просмотра объекта.


══════════════════════════════════════════════════════════════

8. ПРОСМОТР ОБЪЕКТА

При нажатии на карточку объекта
не происходит переход между разделами.

Объект открывается поверх окна чата
в виде модального окна.

После просмотра пользователь возвращается
в переписку автоматически.

При необходимости можно перейти
в полноценный раздел приложения.


══════════════════════════════════════════════════════════════

9. ИСТОРИЯ ОБЩЕНИЯ

Все сообщения сохраняются только
в одном общем чате.

Отдельные переписки внутри:

• тренировок;
• упражнений;
• подходов;
• фотографий;
• веса;
• питания;

не создаются.

Комментарии к объектам через отдельные ветки обсуждения
не используются.

Это исключает дублирование информации
и путаницу между разделами.


══════════════════════════════════════════════════════════════

10. ПОИСК

Поддерживается:

• поиск по словам;
• поиск по датам.

Другие виды поиска не используются.


══════════════════════════════════════════════════════════════

11. REPLY

На любое сообщение можно ответить отдельно.

Reply работает по стандартному принципу,
как в популярных мессенджерах.

В начале сообщения отображается фрагмент сообщения,
на которое был дан ответ,
после чего располагается сам ответ.


══════════════════════════════════════════════════════════════

12. СТАТУСЫ

Используется минимальный набор статусов:

• отправлено;
• прочитано.

Другие статусы не используются.


══════════════════════════════════════════════════════════════

13. ЧЕРНОВИКИ

Если пользователь начал писать сообщение,
но не отправил его,

сообщение автоматически сохраняется
как черновик.

После повторного открытия чата
текст восстанавливается автоматически.

На иконке чата отображается отдельный индикатор черновика,
отличающийся от индикатора непрочитанных сообщений.


══════════════════════════════════════════════════════════════

14. ДВУСТОРОННИЙ ПРИНЦИП

Для клиента и тренера
чат выглядит одинаково.

Используется один и тот же интерфейс.

Отличается только список объектов,
которые доступны конкретному пользователю
в соответствии с его ролью.

Функциональность чата полностью идентична
для обеих сторон.


══════════════════════════════════════════════════════════════

15. АРХИТЕКТУРНЫЙ ПРИНЦИП

Чат не является местом хранения данных.

Все объекты продолжают храниться
только в своих разделах приложения.

Чат отображает ссылки
на существующие объекты платформы
и позволяет быстро открыть их
для обсуждения.

Это исключает дублирование данных
и сохраняет единый источник информации
во всей системе.


══════════════════════════════════════════════════════════════

ПОЖЕЛАНИЯ НА БУДУЩЕЕ (не входят в текущую версию)

• Возможность прикрепления нескольких объектов одним сообщением
при необходимости (решение оставить на будущее; в текущей версии
ориентируемся на принцип «одно сообщение — один объект»).

• Автоматическая расшифровка голосовых сообщений.
Функция признана полезной, но переносится
на более поздний этап разработки,
так как требует дополнительных вычислительных ресурсов
и не является критичной для первой версии продукта.
