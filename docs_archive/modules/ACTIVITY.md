==========================================
РАЗДЕЛ «АКТИВНОСТЬ»
==========================================

ФИЛОСОФИЯ РАЗДЕЛА

Раздел «Активность» предназначен для учета общего уровня физической активности пользователя.

Его задача:

• учитывать ежедневное движение;
• помогать тренеру корректировать тренировочный объем;
• помогать корректировать питание;
• учитывать общий расход энергии;
• формировать аналитику активности.

Раздел не является аналогом Apple Health, Google Fit, Garmin или других фитнес-приложений. Он использует их данные при необходимости, но хранит только ту информацию, которая необходима для тренировочного процесса.

==========================================
КАЛЕНДАРЬ
==========================================

• Любой день открывается нажатием.
• Каждый день представляет собой отдельную страницу активности.
• Структура страницы одинакова для сегодняшнего, вчерашнего или любого другого дня.
• Отдельной истории активности не существует — вся история реализована через календарь.

==========================================
ЦЕЛЬ ПЕРИОДА
==========================================

Под календарем отображается текущая цель периода.

Примеры:

• Повседневная активность.
• Повышенная активность.
• Снижение активности.
• Подготовка к соревнованиям.
• Восстановительный период.

Отображается:

• название периода;
• сроки действия (или бессрочно);
• кнопка «Подробнее».

При раскрытии отображается:

• описание текущего этапа;
• рекомендуемый диапазон шагов;
• рекомендации по кардио;
• комментарии тренера или пользователя.

Если тренера нет — пользователь полностью управляет этим разделом самостоятельно.

Если тренер есть — назначение периода выполняет тренер.

==========================================
ПЛАН НА СЕГОДНЯ
==========================================

Карточка отображается только тогда, когда на конкретный день существуют отдельные назначения.

Например:

• увеличить количество шагов;
• добавить кардио;
• уменьшить активность;
• полностью исключить кардио;
• дополнительные комментарии тренера.

Карточка выделяется более ярким цветом и располагается сразу под целью периода.

При отсутствии индивидуальных назначений карточка не отображается.

==========================================
ШАГИ
==========================================

Главный блок раздела.

Занимает основную часть экрана.

Отображается:

• большое количество шагов;
• выполнено / назначено;
• визуальная шкала выполнения (полукруг или аналогичный индикатор);
• цветовое изменение степени выполнения.

Например:

8742 / 10000

Под блоком отображается источник данных.

Источники:

• Apple Health;
• Health Connect (Android);
• ручной ввод.

Если синхронизация отсутствует — пользователь может вручную указать количество шагов.

==========================================
КАРДИО
==========================================

Кардио существует отдельно от шагов.

Кардио может быть назначено:

• пользователем;
• тренером.

Назначение выполняется по дням недели.

Например:

Понедельник

• дорожка 30 минут

Среда

• велосипед 40 минут

Пятница

• бег 25 минут

На главном экране отображается только краткая информация.

Например:

Кардио

45 / 30 минут

При открытии отображается:

План:

• вид кардио;
• назначенная длительность;
• комментарии.

Факт:

• фактический вид кардио;
• фактическая длительность.

Если кардио не назначалось:

План:

0 минут

Факт:

45 минут

Таким образом пользователь может выполнять кардио сверх назначенного плана.

==========================================
ДОПОЛНИТЕЛЬНАЯ АКТИВНОСТЬ
==========================================

Используется для учета любой активности вне тренировок.

Например:

• футбол;
• баскетбол;
• теннис;
• поход;
• прогулка в горах;
• переезд;
• работа грузчиком;
• любая другая энергозатратная деятельность.

На главном экране отображается только суммарная длительность.

Например:

Дополнительная активность

120 минут

При открытии отображается полный список записей за выбранный день.

Каждая запись содержит:

• название;
• длительность;
• комментарий (необязательно).

Добавление активности осуществляется вручную.

==========================================
ДОБАВЛЕНИЕ АКТИВНОСТИ
==========================================

При нажатии «Добавить активность» пользователь выбирает:

• Кардио.
• Дополнительная активность.

Кардио:

• выбор типа;
• длительность;
• комментарий.

Дополнительная активность:

• свободное название;
• длительность;
• комментарий.

==========================================
ТРЕНЕР И ПОЛЬЗОВАТЕЛЬ
==========================================

Без тренера:

Пользователь самостоятельно:

• назначает цель периода;
• назначает шаги;
• назначает кардио;
• редактирует все данные.

С тренером:

Все назначения выполняет тренер.

Пользователь может:

• просматривать назначения;
• выполнять их;
• заполнять фактические данные.

Редактирование назначений пользователем недоступно.

Во всем разделе используется единый архитектурный принцип платформы:

Самостоятельный пользователь ↔ Пользователь с тренером.

==========================================
АНАЛИТИКА
==========================================

Все данные активности автоматически сохраняются и используются в аналитике.

В дальнейшем возможно отображение:

• среднего количества шагов;
• выполнения плана шагов;
• количества кардио;
• длительности кардио;
• количества дополнительной активности;
• суммарной длительности активности;
• динамики активности за выбранный период.

==========================================
УВЕДОМЛЕНИЯ
==========================================

Раздел активности интегрируется с системой уведомлений главного экрана.

Примеры:

• До выполнения плана осталось пройти 2 300 шагов.

• Сегодня кардио еще не выполнено.

• План активности полностью выполнен.

Уведомления отображаются динамически на главной странице приложения.

==========================================
АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ
==========================================

• Каждая запись активности имеет внутренний уникальный ID.

• Все данные активности сохраняются в базе данных.

• Прошлые записи никогда не изменяются автоматически.

• Все данные доступны аналитике без создания дубликатов.

• Кардио проектируется как расширяемая структура.

На первом этапе используются только:

• тип кардио;
• длительность.

Архитектура должна позволять в будущем без изменения структуры базы добавить:

• дистанцию;
• темп;
• пульс;
• комментарии;
• любые дополнительные параметры.

Все изменения должны быть обратно совместимы с уже существующими данными.
