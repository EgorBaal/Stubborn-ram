# ARCHITECTURE.md

# Архитектура проекта Stubborn Ram

Версия: 0.1

---

# Назначение документа

Этот документ описывает архитектуру проекта Stubborn Ram.

Его задача — объяснить, как устроен проект, как взаимодействуют его части и по каким принципам развивается кодовая база.

Любой новый разработчик должен понимать архитектуру проекта после прочтения данного документа.

---

# Главный принцип

Проект строится по принципу:

**простая архитектура, которую легко расширять.**

Каждый новый модуль должен добавляться без переписывания существующего проекта.

# Назначение папок

## assets

Хранит:

- изображения
- логотипы
- фотографии
- иконки
- видео
- шрифты (при необходимости)

---

## components

Самая большая папка проекта.

Здесь находятся все переиспользуемые компоненты интерфейса.

Каждый самостоятельный блок является отдельным компонентом.

Пример:

```
Hero

FAQ

BeforeAfter

SupportCarousel

Questionnaire
```

---

## pages

Полноценные страницы приложения.

Например:

```
Landing

Client

Coach

Settings

Reports
```

---

## hooks

Пользовательские React Hooks.

Например:

```
useAuth

useReport

useWindowSize
```

---

## services

Работа с внешними сервисами.

Например:

```
Supabase

```

---

## utils

Вспомогательные функции.

Например

```
helpers()
```

---

# Архитектура компонентов

Каждый компонент отвечает только за одну задачу.

Компонент не должен одновременно:

- отображать интерфейс;
- хранить большое количество логики;
- выполнять запросы;
- заниматься валидацией.

По возможности эти обязанности разделяются.

---

# Структура компонентов

Каждый крупный компонент располагается в собственной папке.

Пример

```
Questionnaire/

Questionnaire.jsx

QuestionCard.jsx

QuestionnaireIntro.jsx

questions.js

validation.js

Questionnaire.css
```

# Состояние приложения

На текущем этапе используется React State.

Основное состояние анкеты хранится внутри Questionnaire.

В дальнейшем часть состояния может быть перенесена в глобальное хранилище при необходимости.

До появления реальной необходимости глобальный State не используется.

---

# Работа с API

Любые запросы к серверу должны выполняться только через папку services.

Компоненты интерфейса не должны самостоятельно выполнять HTTP-запросы.

Правильно:

```
Component

↓

service

↓

API
```

Неправильно:

```
Component

↓

fetch()

↓

сервер
```

---

# Работа с CSS

Каждый крупный компонент имеет собственный CSS-файл.

Не создавать один огромный style.css.

Структура должна оставаться модульной.

---

# Масштабирование

При добавлении нового раздела создается новый компонент.

Не расширять существующий компонент бесконечно.

Если файл начинает быстро увеличиваться — его необходимо разделить.

# Архитектурные принципы

✔ Один компонент = одна задача.

✔ Один файл = одна ответственность.

✔ Повторяющийся код выносится.

✔ Не использовать сложные решения без необходимости.

✔ Новые функции должны добавляться без переписывания существующего проекта.

✔ Компоненты должны быть максимально независимыми.

✔ Код должен быть понятен через год без дополнительного объяснения.

---

# Заключение

Архитектура Stubborn Ram строится вокруг простоты, читаемости и масштабируемости.

Проект развивается постепенно.

Каждый новый модуль должен органично встраиваться в существующую структуру без усложнения уже реализованного функционала.
