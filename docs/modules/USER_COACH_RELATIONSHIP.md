# Блок: Взаимодействие пользователя и тренера

Версия: 2.0 (Концепция)

==========================================

1. # ГЛАВНЫЙ ПРИНЦИП (ОБЯЗАТЕЛЬНО)

Stubborn Ram — это персональная платформа пользователя.

Каждый зарегистрированный пользователь получает полноценное приложение для самостоятельного ведения тренировок, питания и прогресса.

Тренер не является обязательной частью системы.

Сопровождение тренером — это дополнительная возможность платформы, которая подключается при необходимости.

Все данные пользователя принадлежат только ему.

========================================== 2. ЕДИНОЕ ЯДРО ПЛАТФОРМЫ (ОБЯЗАТЕЛЬНО)
==========================================

В системе существует одно базовое приложение.

Любой пользователь сразу получает доступ к следующим возможностям:

• профиль;
• тренировки;
• программы тренировок;
• питание;
• дневник питания;
• замеры;
• фотографии;
• видео;
• недельные отчеты;
• история;
• аналитика;
• достижения.

Все эти функции доступны без тренера.

==========================================
ОБЩИЙ АРХИТЕКТУРНЫЙ ПРИНЦИП
ПОЛЬЗОВАТЕЛЬ ↔ ТРЕНЕР
==========================================

Stubborn Ram изначально проектируется как самостоятельная система.

Все функции приложения должны быть полностью доступны пользователю без наличия тренера.

Пользователь может самостоятельно:

• создавать тренировки;
• создавать шаблоны;
• назначать себе питание;
• назначать цели периода;
• назначать кардио;
• устанавливать план шагов;
• вести аналитику;
• формировать отчеты;
• пользоваться библиотекой.

Наличие тренера не добавляет нового функционала.

Тренер лишь получает право управлять уже существующими объектами пользователя.

==========================================

При отсутствии тренера:

Пользователь является владельцем всех своих данных и имеет полный доступ к их созданию, изменению и удалению.

==========================================

При наличии тренера:

Право создания и изменения основных планов переходит тренеру.

Пользователь сохраняет возможность:

• просматривать информацию;
• выполнять назначения;
• заполнять фактические данные;
• формировать отчеты.

Пользователь не может самостоятельно изменять:

• тренировочные планы;
• планы питания;
• цели периода;
• назначенное кардио;
• план шагов;
• другие назначения тренера.

==========================================

Во всех разделах приложения используется единая логика.

Самостоятельный пользователь:

создает → изменяет → выполняет → анализирует.

Пользователь с тренером:

получает назначения → выполняет → анализирует → получает обратную связь.

Таким образом архитектура приложения всегда остается одинаковой.

Меняется только источник назначения:

• пользователь;
или
• тренер.

Все остальные сценарии работы приложения остаются неизменными.

========================================== 3. ПОДКЛЮЧАЕМЫЕ МОДУЛИ (ОБЯЗАТЕЛЬНО)
==========================================

Дополнительный функционал подключается поверх базового приложения.

На текущем этапе предусмотрены следующие модули:

• сопровождение тренером;
• инструменты тренера;
• маркетплейс тренеров.

Подключение новых модулей не изменяет базовую архитектуру приложения.

========================================== 4. ВЛАДЕНИЕ ДАННЫМИ (ОБЯЗАТЕЛЬНО)
==========================================

Все данные принадлежат пользователю:

• профиль;
• вес;
• замеры;
• фотографии;
• видео;
• программы;
• питание;
• дневник;
• отчеты;
• история;
• достижения;
• заметки;
• переписка.

Ни один тренер не становится владельцем этих данных.

========================================== 5. ОТЧЕТЫ (ОБЯЗАТЕЛЬНО)
==========================================

Недельный отчет является личным объектом пользователя.

Он создается независимо от наличия тренера.

Каждый пользователь может:

• сформировать отчет;
• сохранить его;
• просматривать историю своих отчетов;
• анализировать собственный прогресс.

Если у пользователя есть активное сотрудничество с тренером, появляется возможность поделиться отчетом.

При этом отчет не копируется и не переносится.

Он продолжает существовать как часть личной истории пользователя.

Тренер получает право просматривать этот отчет в рамках периода активного сотрудничества.

========================================== 6. ПОДКЛЮЧЕНИЕ ТРЕНЕРА (ОБЯЗАТЕЛЬНО)
==========================================

Пользователь может в любой момент:

• подключить тренера;
• отключить тренера;
• сменить тренера;
• вернуться к прежнему тренеру.

Все действия выполняются без создания нового аккаунта.

При подключении тренера пользователь предоставляет ему доступ к своим данным.

========================================== 7. ДОСТУП К ДАННЫМ (ОБЯЗАТЕЛЬНО)
==========================================

Все данные пользователя существуют в единственном экземпляре.

Во время активного сотрудничества тренер получает доступ к данным пользователя, относящимся к данному периоду сотрудничества.

После завершения сотрудничества:

• новые данные пользователя тренеру больше не доступны;
• данные, созданные во время совместной работы, остаются доступными обеим сторонам;
• пользователь продолжает пользоваться всеми функциями платформы без каких-либо ограничений.

Передача данных между пользователем и тренером осуществляется путем предоставления доступа, а не путем создания копий объектов.

========================================== 8. СВЯЗЬ "ТРЕНЕР — ПОЛЬЗОВАТЕЛЬ" (ОБЯЗАТЕЛЬНО)
==========================================

Связь между тренером и пользователем никогда не удаляется.

Она хранит историю сотрудничества и определяет период, в течение которого тренер имеет доступ к данным пользователя.

Связь имеет два состояния.

ACTIVE

• активное сопровождение;
• доступ к текущим данным пользователя;
• получение новых отчетов;
• создание программ;
• комментарии;
• обмен сообщениями.

ARCHIVED

• история сотрудничества сохраняется;
• новые данные пользователя больше не отображаются;
• остается доступ ко всем данным, созданным во время периода сотрудничества;
• редактирование прекращается;
• уведомления отключаются.

Именно связь между пользователем и тренером определяет, какие данные доступны тренеру, а не отдельные объекты системы.

========================================== 8. ЕДИНСТВЕННЫЙ ЭКЗЕМПЛЯР ДАННЫХ (ОБЯЗАТЕЛЬНО)
==========================================

Любой объект системы существует только в одном экземпляре.

Это относится ко всем сущностям платформы:

• отчетам;
• фотографиям;
• замерам;
• программам;
• комментариям;
• тренировкам;
• данным питания;
• достижениям.

При взаимодействии с тренером новые объекты не создаются и существующие не копируются.

Изменяются только права доступа к данным в рамках активного периода сотрудничества.

Такой подход обеспечивает целостность данных, исключает дублирование информации и упрощает дальнейшее развитие архитектуры проекта.

========================================== 11. ИНСТРУМЕНТЫ ТРЕНЕРА (ОБЯЗАТЕЛЬНО)
==========================================

Любой пользователь может получить доступ к инструментам тренера.

После подключения данного модуля становятся доступны:

• список клиентов;
• создание программ;
• ответы на отчеты;
• просмотр прогресса клиентов;
• управление сопровождением.

При этом пользователь продолжает пользоваться своим личным кабинетом как обычный пользователь.

========================================== 12. ПЕРЕКЛЮЧЕНИЕ РЕЖИМОВ (ОБЯЗАТЕЛЬНО)
==========================================

Если пользователь обладает доступом к инструментам тренера, в профиле появляется переключатель режима.

Режим пользователя

↓

Режим тренера

Переключение изменяет только интерфейс и доступные инструменты.

Все данные остаются частью одного аккаунта.

Тренер может одновременно:

• вести собственный прогресс;
• заниматься самостоятельно;
• быть подопечным другого тренера;
• сопровождать собственных клиентов.

========================================== 13. ПРИГЛАШЕНИЕ ТРЕНЕРОМ (ЖЕЛАТЕЛЬНО)
==========================================

Тренер не создает пользователей.

Тренер отправляет приглашение.

Пользователь принимает приглашение.

После подтверждения создается связь между пользователем и тренером.

Аккаунт всегда принадлежит пользователю.

========================================== 14. МАРКЕТПЛЕЙС ТРЕНЕРОВ (НА БУДУЩЕЕ)
==========================================

Пользователь может найти тренера внутри платформы.

Маркетплейс включает:

• каталог тренеров;
• профиль тренера;
• фильтрацию;
• поиск;
• рейтинги;
• отзывы;
• возможность подключения к тренеру.

Маркетплейс является независимым модулем и не влияет на архитектуру основной платформы.

========================================== 16. РАЗВИТИЕ АРХИТЕКТУРЫ (НА БУДУЩЕЕ)
==========================================

Архитектура должна позволять добавить без изменения существующей структуры:

• нескольких тренеров;
• нутрициолога;
• реабилитолога;
• врача;
• других специалистов.

==========================================

• передача клиента другому тренеру;
• выбор данных, которыми пользователь хочет поделиться;
• временная пауза сопровождения;
• несколько специалистов одновременно;
• индивидуальные права доступа;
• экспорт истории;
• импорт данных из других сервисов.

==========================================
БУДУЩЕЕ РАСШИРЕНИЕ
==========================================

Раздел «Медиа»

Отдельное хранилище пользовательских фотографий и видео.

Не относится к контрольным точкам.

Назначение:

• фотографии на пампе;
• фотографии в удачном освещении;
• фотографии с соревнований;
• произвольные фотографии формы;
• видео позирования;
• мотивационные фотографии;
• любые личные материалы пользователя.

Поддерживается:

• создание папок;
• избранное;
• сортировка;
• постоянное хранение;
• возможность делиться с тренером.

Контрольные точки остаются отдельным независимым разделом и содержат только стандартизированные данные для объективного сравнения прогресса.

==========================================
ГЛАВНАЯ ИДЕЯ ПРОЕКТА
==========================================

Stubborn Ram — это единая персональная платформа для ведения тренировок, питания и прогресса.

Каждый пользователь может использовать платформу полностью самостоятельно.

При необходимости он может подключить одного или нескольких специалистов, предоставив им доступ к своим данным.

Тренеры, специалисты и дополнительные сервисы являются подключаемыми модулями платформы, а не отдельными версиями приложения.

Все данные всегда принадлежат пользователю.

Тренеры приходят и уходят.

История пользователя остается с ним навсегда.
