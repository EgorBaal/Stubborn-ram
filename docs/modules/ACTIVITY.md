# ACTIVITY

## Назначение

Модуль ACTIVITY должен описывать учёт повседневной активности пользователя: шаги, кардио и дополнительную активность.
В текущей ветке модуль существует как экран-заглушка без подтверждённой backend-подсистемы.

## Статус

**PARTIALLY IMPLEMENTED** — маршрут и UI-заглушка существуют, но рабочая модель хранения и выделенный backend отсутствуют.

Термины статусов:

- **CURRENT** — подтверждено кодом и backend.
- **PARTIALLY IMPLEMENTED** — есть только часть UI или отдельные элементы сценария.
- **PLANNED** — описано как целевое состояние, но не реализовано.
- **DEFERRED** — отложено до следующих этапов.
- **NOT VERIFIED** — поведение не подтверждено кодом.

## Текущая реализация

Подтверждено по коду:

- маршрут `/app/activity` подключён в маршрутизатор;
- в `Home` есть ссылка на `/app/activity`;
- `ActivityPlaceholderPage` отображает заголовок и сообщение о разработке.

Не подтверждено:

- список записей активности;
- календарь активности;
- отдельные записи шагов, кардио и дополнительной активности;
- backend API и persistence для activity domain.

## UI / Экраны

Текущий экран:

- `ActivityPlaceholderPage`.

Текущее содержимое:

- заголовок «Активность»;
- текст-заглушка «Раздел находится в разработке.».

## Текущий flow

1. Пользователь открывает `/app/activity`.
2. Отображается экран-заглушка.
3. Дальнейший сценарий учёта активности не реализован в текущей ветке.

## Данные / Хранение

Текущее состояние:

- persistence активности во frontend не реализована;
- выделенная модель данных activity в backend не обнаружена;
- нет подтверждённых таблиц или миграций для activity module.

## Backend

Проверка backend показала:

- выделенные маршруты activity не обнаружены;
- выделенные таблицы или миграции activity не обнаружены;
- выделенный service activity не обнаружен.

Вывод: backend activity subsystem в текущем snapshot отсутствует.

## Связи с другими модулями

Текущие видимые связи:

- `Home` содержит навигационную карточку на `/app/activity`;
- `Activity` концептуально связан с `Training`, `Food`, `Weight` и `PHOTO_AND_MEASUREMENTS`, но отдельной рабочей интеграции пока нет.

## PARTIALLY IMPLEMENTED

- маршрут есть;
- UI-заглушка есть;
- backend/persistence нет.

## PLANNED

- календарный учёт активности;
- шаги, кардио, дополнительная активность;
- цели периода и назначенные значения;
- аналитика активности;
- связь с тренером и назначениями.

## DEFERRED / NOT VERIFIED

- **DEFERRED**: расширенная синхронизация с внешними health-платформами и углублённые аналитические сценарии.
- **NOT VERIFIED**: полный жизненный цикл activity, потому что выделенный backend отсутствует.

## Известные ограничения

- модуль ограничен экраном-заглушкой;
- нет подтверждённого backend API;
- нет подтверждённой истории активности или persistence.
