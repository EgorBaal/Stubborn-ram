# PHOTO_AND_MEASUREMENTS

## Назначение

Модуль PHOTO_AND_MEASUREMENTS должен обеспечивать контрольные фотографии и измерения пользователя.
В текущей ветке модуль реализован частично: есть загрузка фото через общий media subsystem, но отдельная подсистема измерений отсутствует.

## Статус

**PARTIALLY IMPLEMENTED** — сценарий работы с фото частично доступен, сценарий измерений не подтверждён.

## Текущая реализация

Подтверждено по коду:

- маршрут `/app/photos` подключён в маршрутизатор;
- `PhotosPlaceholderPage` отображает текст о проверке загрузки фотографий через Media API;
- внутри страницы используется `PhotoUploader`;
- `PhotoUploader` работает через общий `mediaService` (`/media/upload`, `/media/:id/complete`, `/media/:id`).

Не подтверждено:

- отдельные экраны измерений;
- выделенный backend для измерений;
- сравнение контрольных точек;
- история замеров как отдельная доменная сущность.

## UI / Экраны

Текущий экран:

- `PhotosPlaceholderPage`.

Дополнительный frontend-компонент:

- `PhotoUploader`.

Текущее содержимое:

- экран-заглушка «Фото и замеры»;
- UI загрузки фото;
- просмотр загруженных изображений;
- удаление изображений;
- зум и просмотр в `PhotoUploader`.

## Фото

Текущее фото-состояние:

- можно загружать изображения через общий сценарий media;
- `PhotoUploader` ограничивает типы файлов JPG, PNG и WebP;
- есть локальный viewer и удаление фотографии;
- фото после загрузки хранятся как media objects, а не как отдельная photo domain entity.

## Измерения

Текущее состояние измерений:

- отдельного UI для измерений не найдено;
- отдельного backend для измерений не найдено;
- подтверждённой модели замеров в текущей ветке нет.

## Данные / Хранение

Текущее состояние:

- фото используют общий media subsystem;
- отдельная persistence-модель `PHOTO_AND_MEASUREMENTS` не обнаружена;
- измерения как отдельный тип данных не подтверждены.

## Media integration

В модуле используется общий `mediaService`:

- `createMediaUpload`
- `completeMediaUpload`
- `getMedia`
- `deleteMedia`

Это означает, что фото-интеграция опирается на общий media layer, а не на отдельный photo/measurements backend.

## Backend

Проверка backend показала:

- выделенные маршруты photo & measurements не обнаружены;
- выделенные таблицы или миграции photo & measurements не обнаружены;
- загрузка фото работает через общий `media` backend, а не через отдельный доменный модуль.

## Текущий flow

1. Пользователь открывает `/app/photos`.
2. Видит экран-заглушку и `PhotoUploader`.
3. Загружает изображения через общий сценарий media.
4. Отдельный сценарий для измерений в текущей ветке отсутствует.
