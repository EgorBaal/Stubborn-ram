STUBBORN RAM — ТРЕНИРОВКИ 2.0
ЗАФИКСИРОВАННЫЕ РЕШЕНИЯ И ЛОГИКА

Дата фиксации: 14.09.2026

Этот файл содержит только решения, которые были обсуждены и закреплены в текущей работе над разделом тренировок. Не добавлять новые предположения без отдельного согласования.

1. ОСНОВНЫЕ СУЩНОСТИ

Шаблон — самостоятельная заготовка тренировки.
Тренировочная программа — отдельная сущность-контейнер, объединяющая несколько тренировочных протоколов.
Тренировочный протокол — конкретная тренировка внутри конкретной программы.
Тренировка — конкретный экземпляр, который пользователь создаёт/проводит.
История — место хранения созданных и проведённых конкретных тренировок.

Протоколы внутри программ НЕ являются глобальными шаблонами и не должны автоматически появляться в разделе «Шаблоны».

2. ГЛАВНЫЙ ПРИНЦИП: КОПИРОВАНИЕ, А НЕ СВЯЗЬ

Шаблон — просто заготовка. При использовании его данные копируются в новую тренировку. После копирования новая тренировка полностью независима от шаблона.

Изменения шаблона влияют только на будущие копирования. Уже созданная тренировка не меняется.

То же самое относится к тренировочному протоколу внутри программы: при запуске создаётся независимая копия в виде конкретной тренировки.

3. ШАБЛОНЫ

Шаблон создаётся в разделе «Шаблоны».

В шаблоне сохраняются данные, необходимые для заготовки тренировки:

- название;
- комментарий;
- упражнения;
- порядок упражнений;
- подходы;
- веса, повторы, RIR/RPE, отдых, методы интенсивности и другие уже поддерживаемые параметры.

После использования шаблона пользователь может полностью изменить созданную тренировку, вплоть до удаления всех упражнений и сборки тренировки заново.

Такая тренировка не сохраняется автоматически обратно в «Шаблоны».

4. ТРЕНИРОВОЧНАЯ ПРОГРАММА

Программа — постоянная структура с последовательностью тренировочных протоколов.

Для программы сейчас закреплены:

- точное название;
- комментарий / описание;
- авторство.

Авторство определяется системой автоматически по ID пользователя, который создал сущность. Вручную текст автора не вводится.

Если создал тренер, система должна знать ID тренера и может отображать его имя и аватар. Если создал клиент — соответствующего пользователя.

Недельный объём пока не вводится вручную и отдельным параметром сейчас не реализуется. В будущем планируется автоматический подсчёт общего недельного объёма и затем объёма по мышечным группам.

5. ПРОТОКОЛЫ ВНУТРИ ПРОГРАММЫ

В программе может быть сколько угодно протоколов.

Обязательно:

- добавить протокол;
- удалить протокол;
- изменить порядок протоколов.

Пока протоколы идут просто последовательно. Привязка к понедельнику/среде/пятнице, календарю и конкретным неделям пока не добавляется.

Способ визуальной перестановки будет определён позже.

6. СОЗДАНИЕ ПРОТОКОЛА

При «Добавить тренировку» внутри программы открывается по сути тот же конструктор, что и для обычной новой тренировки.

Используется существующий TrainingPage как единый конструктор, а не отдельная полностью новая система.

В протокол можно:

- скопировать существующий глобальный шаблон;
- либо собрать протокол с нуля.

Если протокол создан из шаблона, исходный шаблон остаётся неизменным.

Протокол, созданный с нуля внутри программы, существует только внутри этой программы и в глобальные «Шаблоны» не попадает.

Протокол можно позже редактировать. Изменённый протокол используется при следующих запусках.

7. TRAININGPAGE

TrainingPage должен по возможности быть единым конструктором для:

- обычной тренировки;
- создания/редактирования протокола;
- использования протокола для создания конкретной тренировки.

Не создавать отдельную копию конструктора только для протоколов.

Конкретная реализация режимов будет определена при разработке.

8. ДАТА И ВРЕМЯ

Дата и время НЕ являются свойствами шаблона или тренировочного протокола.

В протокол не входят:

- дата;
- время начала;
- время окончания;
- статус завершения.

Эти данные относятся к конкретной тренировке.

При использовании шаблона или протокола создаётся новая конкретная тренировка, и дата/время относятся уже к ней.

Пример:
Протокол «Грудь + плечи» → тренировка 14.09.2026 18:42.
Следующее использование → другая тренировка с другой датой/временем.

Уже созданная тренировка не должна автоматически получать новую дату/время при повторном открытии.

Текущую реализацию TrainingPage с датой/временем нужно отдельно проверить, чтобы убедиться, что такого изменения не происходит.

9. ИСПОЛЬЗОВАНИЕ ПРОТОКОЛА

Пользователь открывает программу, выбирает конкретный протокол и запускает его.

Создаётся новая конкретная тренировка. В неё копируется содержимое протокола:

- название;
- комментарий;
- упражнения;
- порядок;
- подходы;
- веса;
- повторы;
- RIR/RPE;
- отдых;
- методы интенсивности;
- другие сохранённые параметры.

Дата и время берутся из конкретной текущей тренировки.

После создания тренировку можно менять независимо от протокола.

После завершения она попадает в Историю.

10. ИСТОРИЧЕСКИЙ СЛЕПОК ПРОГРАММЫ

Для тренировки, созданной из протокола программы, нужен независимый исторический слепок.

Это не просто ссылка на текущую программу.

В момент создания тренировки сохраняется состояние программы и контекст протокола на этот момент, включая:

- название программы;
- комментарий / описание;
- автора;
- информацию о протоколе;
- упражнения и параметры протокола;
- другие данные программы, которые в будущем будут иметь историческое значение.

После этого изменения текущей программы не меняют слепок.

11. ССЫЛКА ИЗ ИСТОРИИ

В Истории тренировка, созданная из программы, должна иметь дополнительную пометку, например:

«Грудь»
«Из программы "Верх-низ от Георгия"»

Пометка должна быть кликабельной.

При нажатии открывается именно исторический слепок состояния программы/протокола на момент создания тренировки, а НЕ текущая программа.

Так спустя время можно посмотреть, как тогда выглядела программа, её описание, автор, протокол и его содержание.

12. ИЗМЕНЕНИЯ ПРОГРАММЫ

Программа является текущей рабочей структурой.

Если программа назначена клиенту и тренер её изменил:

- текущая программа клиента изменяется;
- следующие тренировки используют уже изменённые протоколы.

Ранее созданные/проведённые тренировки не изменяются, не пересчитываются и не получают новые данные.

Для них сохраняется исторический слепок.

13. ТРЕНЕР И КЛИЕНТ

Конкретный интерфейс назначения программы клиенту пока НЕ утверждён.

Обсуждались варианты:

- тренер работает через специальный режим просмотра аккаунта клиента;
- тренер создаёт программу у себя и затем назначает её клиенту.

Окончательный вариант пока не выбран.

Зафиксировано: если действие выполнено тренером, система должна знать реального пользователя-тренера по ID, а не через вручную написанный текст.

Тренерский доступ предполагается преимущественно read-only с отдельными разрешёнными действиями редактирования. Конкретные права должны соответствовать существующей архитектуре разрешений проекта.

14. РЕДАКТИРОВАНИЕ

В дальнейшем из режима просмотра/использования должна быть возможность перейти в режим «Изменить».

Это относится к:

- шаблонам;
- протоколам;
- программам;
- конкретным тренировкам.

Внешний вид кнопок и экранов пока не фиксирован.

15. ОСНОВНАЯ ЦЕПОЧКА

Самостоятельный шаблон:

ШАБЛОН
↓ копирование
ТРЕНИРОВКА
↓
ИСТОРИЯ

Программа:

ПРОГРАММА
↓
ТРЕНИРОВОЧНЫЙ ПРОТОКОЛ
↓ копирование
ТРЕНИРОВКА
↓
ИСТОРИЯ

- ИСТОРИЧЕСКИЙ СЛЕПОК ПРОГРАММЫ/ПРОТОКОЛА

Главный принцип: копирование создаёт независимую сущность. Изменения источника не изменяют уже созданную копию.

16. ПОКА НЕ РЕАЛИЗУЕМ

Пока не определены/не реализуются:

- календарная привязка протоколов;
- сложная система версий программы;
- маркетплейс готовых программ;
- продажа программ;
- расширенный недельный объём по мышечным группам;
- конкретный UX назначения программы клиенту;
- конкретный UX перестановки протоколов.

17. СУЩЕСТВУЮЩАЯ РАБОЧАЯ ОСНОВА

Существующее сохранение конкретных тренировок уже работает и не должно ломаться.

Текущая структура конкретной тренировки:

workouts
└── workout_exercises
└── workout_sets

Она остаётся основой для конкретных тренировок и Истории.

Новые сущности шаблонов, программ и протоколов должны добавляться поверх существующей рабочей части, не разрушая текущее сохранение тренировок.

18. СЛЕДУЮЩИЙ ЭТАП

Перед миграциями определить точную структуру хранения:

- самостоятельных шаблонов;
- упражнений и подходов шаблонов;
- программ;
- протоколов внутри программ;
- упражнений и подходов протоколов;
- создания независимой тренировки;
- исторического слепка программы/протокола.

После утверждения структуры переходить к миграциям и реализации.

Не изменять существующие применённые миграции задним числом.
Не ломать существующее сохранение тренировок.
