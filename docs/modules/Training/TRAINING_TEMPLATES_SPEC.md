STUBBORN RAM — АРХИТЕКТУРА ШАБЛОНОВ ТРЕНИРОВОК

Зафиксированная логика и назначение шаблонов.

1. НАЗНАЧЕНИЕ ШАБЛОНА

Шаблон — это сохранённая заготовка тренировки, которая нужна для того, чтобы пользователь не вводил одни и те же упражнения и параметры заново.

Шаблон не является выполненной тренировкой и не попадает в Историю.

Шаблон хранит собранную пользователем конфигурацию тренировки на момент сохранения.

2. СОЗДАНИЕ ШАБЛОНА

Путь:

Тренировки → Шаблоны → Создать шаблон

После нажатия «Создать шаблон» открывается тот же основной экран конструктора тренировки, который уже существует в проекте (TrainingPage и его компоненты).

Пользователь собирает шаблон так же, как обычную тренировку:

- название;
- упражнения;
- порядок упражнений;
- подходы;
- веса;
- повторы;
- RIR/RPE;
- отдых;
- комментарии;
- суперсеты;
- intensity methods;
- другие сохраняемые параметры.

После нажатия «Сохранить шаблон» данные сохраняются как шаблон.

При этом Workout не создаётся и запись в Истории не появляется.

3. СПИСОК ШАБЛОНОВ

В разделе «Шаблоны» отображаются все сохранённые пользователем шаблоны.

Например:

Бицепс
Трицепс
Грудь
Ноги
Плечи

Количество шаблонов не ограничивается.

Один и тот же список сохранённых шаблонов является единым источником данных.

Страница «Шаблоны» и экран «Создать тренировку» должны показывать одни и те же сохранённые шаблоны, а не иметь собственные hardcoded-списки.

4. СОЗДАНИЕ ТРЕНИРОВКИ

Пользователь заходит:

История → Создать тренировку

На экране доступны два варианта:

1. «Новая тренировка»
2. сохранённые шаблоны пользователя.

Если выбрана «Новая тренировка», открывается пустой TrainingPage.

Если выбран шаблон, например «Бицепс», открывается TrainingPage, уже заполненный данными этого шаблона.

5. КОПИРОВАНИЕ ШАБЛОНА

Выбор шаблона НЕ открывает шаблон для изменения.

Выбор шаблона создаёт независимую копию его текущего содержимого для новой тренировки.

Схема:

Шаблон «Бицепс»
↓
COPY
↓
Новая тренировка

В копию переносятся:

- упражнения;
- порядок упражнений;
- комментарии упражнений;
- суперсеты;
- подходы;
- веса;
- повторы;
- RIR/RPE;
- отдых;
- intensity methods;
- остальные сохранённые параметры шаблона.

6. НЕЗАВИСИМОСТЬ КОПИИ

После создания копии связь с исходным шаблоном прекращается.

Пользователь может полностью изменить новую тренировку:

- изменить вес;
- изменить повторы;
- изменить RIR/RPE;
- добавить упражнения;
- удалить упражнения;
- изменить подходы;
- изменить комментарии;
- полностью очистить тренировку.

Ни одно из этих действий не должно изменять исходный шаблон.

Например:

Шаблон «Бицепс»
Подъём штанги — 40 кг × 10

Новая тренировка из шаблона:
Подъём штанги — 50 кг × 8

Шаблон по-прежнему остаётся:
40 кг × 10

7. ЗАВЕРШЕНИЕ ТРЕНИРОВКИ

После нажатия «Завершить» созданная из шаблона копия становится обычной выполненной тренировкой.

Она сохраняется как Workout и появляется в Истории.

Исходный шаблон при этом остаётся неизменным и продолжает находиться в разделе «Шаблоны».

Один шаблон можно использовать многократно.

Например:

Шаблон «Бицепс»
↓
тренировка 14.09
↓
тренировка 18.09
↓
тренировка 23.09

Каждая тренировка является отдельной записью Истории.

8. РАЗДЕЛЕНИЕ ДАННЫХ

Шаблоны и выполненные тренировки должны храниться отдельно.

Структура:

users
├── workouts
│ └── workout_exercises
│ └── workout_sets
│
└── training_templates
└── training_template_exercises
└── training_template_sets

Не использовать workouts для хранения шаблонов.

Шаблон является отдельной сущностью.

9. ДАННЫЕ ШАБЛОНА

В шаблоне сохраняются:

- название;
- тип тренировки;
- комментарий;
- упражнения;
- порядок;
- параметры упражнений;
- подходы и их параметры.

Дата конкретной тренировки, время начала, время окончания и completed_at не являются свойствами шаблона.

Когда пользователь создаёт тренировку из шаблона, новая тренировка получает собственную дату и время.

10. BACKEND API

Для шаблонов предусмотрены отдельные API:

GET /api/training/templates
POST /api/training/templates
GET /api/training/templates/:id
PUT /api/training/templates/:id
DELETE /api/training/templates/:id

Все операции выполняются с учётом текущего авторизованного пользователя.

11. РОЛЬ ТЕКУЩИХ FRONTEND-ФАЙЛОВ

TrainingTemplatesPage.jsx
— страница списка сохранённых шаблонов и перехода к созданию шаблона.

TrainingTemplateBuilderPage.jsx
— экран создания/редактирования шаблона; должен использовать существующую структуру конструктора тренировки, а не создавать отдельный несовместимый UI.

TrainingCreateList.jsx
— список вариантов при создании тренировки; hardcoded тестовые шаблоны должны быть удалены и заменены реальными сохранёнными шаблонами.

TrainingPage.jsx
— основной конструктор тренировки; должен поддерживать обычное создание тренировки и загрузку данных выбранного шаблона в новую независимую тренировку.

trainingService.js
— клиентские методы работы с API тренировок и отдельные методы работы с шаблонами.

12. ГЛАВНЫЙ ПРИНЦИП

Шаблон = первоисточник-заготовка.

Выбор шаблона = создание независимой копии его текущего содержимого в новую тренировку.

Изменение новой тренировки никогда не изменяет исходный шаблон.

Шаблон можно использовать многократно.
