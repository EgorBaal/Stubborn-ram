Данный документ описывает общие принципы работы платформы
Stubborn Ram.

Он определяет:

• роли пользователей;
• жизненный цикл пользователя;
• правила подключения тренера;
• владение данными;
• взаимодействие между пользователем и тренером.

Документ не описывает интерфейс отдельных разделов
(тренировки, питание, вес и т.д.).
Они вынесены в самостоятельные архитектурные документы.


══════════════════════════════════════════════════════════════

1. ТИПЫ ПОЛЬЗОВАТЕЛЕЙ

Платформа поддерживает три режима работы.

1. Самостоятельный пользователь.

Пользуется приложением самостоятельно,
сам создает тренировки, питание, цели,
контрольные точки и отчеты.

────────────────────────────────────────────

2. Пользователь с тренером.

Работает внутри платформы
под сопровождением тренера.

Большинство назначений формируются тренером.

────────────────────────────────────────────

3. Тренер.

Использует отдельный интерфейс тренера
для управления клиентами.

Архитектура кабинета тренера
описывается отдельным документом.


══════════════════════════════════════════════════════════════

2. ПОДКЛЮЧЕНИЕ К ТРЕНЕРУ

Каждый тренер имеет:

• внутренний системный ID
(неизменяемый);

• код приглашения.

Код приглашения используется
для подключения клиентов.

Клиент получает код от тренера
любым удобным способом
(мессенджер, лично, QR-код, ссылка и т.д.).

После ввода кода
система показывает найденного тренера.

После подтверждения
создается запрос на подключение.


══════════════════════════════════════════════════════════════

3. СТАРТОВАЯ АНКЕТА

После подключения
открывается обязательная стартовая анкета.

До ее заполнения
полноценное использование платформы
невозможно.

Анкета отправляется тренеру.

После изучения анкеты
тренер принимает решение
о начале сотрудничества.


══════════════════════════════════════════════════════════════

4. ПРИНЯТИЕ ИЛИ ОТКАЗ

Тренер может:

• принять клиента;

или

• отказать.

При отказе:

• связь не создается;

• пользователь сохраняет аккаунт
и все свои данные;

• пользователь может оформить
самостоятельную подписку
или подключиться к другому тренеру.


══════════════════════════════════════════════════════════════

5. ВЛАДЕНИЕ ДАННЫМИ

Все данные принадлежат пользователю.

При подключении тренера
пользователь самостоятельно выбирает:

• предоставить всю историю;

• предоставить данные
только с момента подключения;

• выбрать период вручную.


══════════════════════════════════════════════════════════════

6. ЗАВЕРШЕНИЕ СОТРУДНИЧЕСТВА

Завершить сотрудничество
может любая сторона.

Перед завершением
обязательно появляется подтверждение действия.

После завершения:

• связь разрывается;

• история полностью сохраняется;

• пользователь может
продолжить пользоваться платформой
самостоятельно;

или

подключить нового тренера.


══════════════════════════════════════════════════════════════

7. ОТЧЕТЫ

Если пользователь работает самостоятельно —

день отчета
назначает самостоятельно.

Если пользователь работает с тренером —

день отчета
назначает тренер.

Дата может изменяться
в дальнейшем.


══════════════════════════════════════════════════════════════

8. ПАУЗА

Должен существовать режим
временной паузы.

Например:

• болезнь;

• отпуск;

• командировка;

• соревнования;

• другое.

Во время паузы:

• отключаются напоминания;

• не требуется отправка отчетов;

• история не прерывается;

• все данные продолжают сохраняться.


══════════════════════════════════════════════════════════════

9. ОБЩИЕ ПРИНЦИПЫ

• Один аккаунт может менять свою роль
(самостоятельный пользователь,
клиент тренера,
тренер).

• Все данные пользователя
сохраняются независимо
от изменения роли.

• При смене тренера
данные пользователя
не удаляются.

• Архитектура платформы
строится вокруг единого аккаунта пользователя.

ВОПРОСЫ,
ТРЕБУЮЩИЕ ОБСУЖДЕНИЯ

1.

Первый запуск приложения.

Какие данные являются обязательными
при регистрации,
а какие можно заполнить позже.

────────────────────────────────────────────

2.

Подписки.

• самостоятельная подписка;

• тренерская подписка;

• ограничения бесплатной версии;

• окончание подписки.

────────────────────────────────────────────

3.

Переход между ролями.

• самостоятельный → клиент;

• клиент → самостоятельный;

• тренер → обычный пользователь.

────────────────────────────────────────────

4.

Работа с несколькими тренерами.

Может ли пользователь
быть одновременно
подключен к нескольким тренерам,
или всегда только к одному.

────────────────────────────────────────────

5.

Передача клиента
другому тренеру.

Что передается новому тренеру,
что остается у предыдущего.

────────────────────────────────────────────

6.

Удаление аккаунта.

Что происходит:

• с историей;

• с отчетами;

• с фотографиями;

• с аналитикой;

• с привязкой к тренеру.
