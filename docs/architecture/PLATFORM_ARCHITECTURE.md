АРХИТЕКТУРА ПЛАТФОРМЫ
Версия 1.0 (утверждено)
══════════════════════════════════════════════════════════════

Данный документ описывает общие принципы работы платформы
Stubborn Ram.

Он определяет:

• статусы использования платформы;
• жизненный цикл пользователя;
• правила подключения тренера;
• владение данными;
• взаимодействие между пользователем и тренером.

Документ не описывает интерфейс отдельных разделов
(тренировки, питание, вес и т.д.).
Они вынесены в самостоятельные архитектурные документы.

══════════════════════════════════════════════════════════════

1. СТАТУСЫ ИСПОЛЬЗОВАНИЯ ПЛАТФОРМЫ

Платформа использует единый аккаунт пользователя.

Аккаунт может одновременно обладать одним или несколькими статусами использования.

На текущем этапе предусмотрены следующие статусы:

• Самостоятельный пользователь.

Использует платформу самостоятельно.

•

Клиент.

Работает под сопровождением тренера.

•

Тренер.

Использует инструменты сопровождения клиентов.

Статусы использования могут изменяться без создания нового аккаунта.

Все пользовательские данные, история и подписки при этом сохраняются.

══════════════════════════════════════════════════════════════

2. ПОДКЛЮЧЕНИЕ К ТРЕНЕРУ

Каждый тренер имеет:

• внутренний системный ID
(неизменяемый);

• код приглашения.

Код приглашения используется
для подключения клиентов.

Клиент получает код от тренера
любым удобным способом
(мессенджер, лично, QR-код, ссылка и т.д.).

После ввода кода
система показывает найденного тренера.

После подтверждения
создается запрос на подключение.

До подтверждения запроса тренером связь между пользователем и тренером не считается созданной.

══════════════════════════════════════════════════════════════

3. СТАРТОВАЯ АНКЕТА

После подключения
открывается обязательная стартовая анкета.

До ее заполнения
полноценное использование платформы
невозможно.

Анкета отправляется тренеру.

После изучения анкеты
тренер принимает решение
о начале сотрудничества.

══════════════════════════════════════════════════════════════

4. ПРИНЯТИЕ ИЛИ ОТКАЗ

Тренер может:

• принять клиента;

или

• отказать.

При отказе:

• связь не создается;

• пользователь сохраняет аккаунт
и все свои данные;

• пользователь может оформить
самостоятельную подписку
или подключиться к другому тренеру.

══════════════════════════════════════════════════════════════

5. ВЛАДЕНИЕ ДАННЫМИ

Все пользовательские данные принадлежат пользователю.

При подключении тренера доступ к данным определяется правилами платформы.

Модель предоставления доступа к ранее созданной истории будет определена отдельным архитектурным решением.

══════════════════════════════════════════════════════════════

6. ЗАВЕРШЕНИЕ СОТРУДНИЧЕСТВА

Завершить сотрудничество
может любая сторона.

Перед завершением
обязательно появляется подтверждение действия.

После завершения:

• связь переводится в архивное состояние;

• история сотрудничества сохраняется для последующего просмотра и аудита изменений;

• пользователь может
продолжить пользоваться платформой
самостоятельно;

или

подключить нового тренера.

══════════════════════════════════════════════════════════════

7. ОТЧЕТЫ

Если пользователь работает самостоятельно —

день отчета
назначает самостоятельно.

Если пользователь работает с тренером —

день отчета
назначает тренер.

Дата может изменяться
в дальнейшем.

══════════════════════════════════════════════════════════════

8. ПАУЗА

Должен существовать режим
временной паузы.

Например:

• болезнь;

• отпуск;

• командировка;

• соревнования;

• другое.

Во время паузы:

• отключаются напоминания;

• не требуется отправка отчетов;

• история не прерывается;

• все данные продолжают сохраняться.

══════════════════════════════════════════════════════════════

9. ОБЩИЕ ПРИНЦИПЫ

• Один аккаунт может менять свои статусы использования
(самостоятельный пользователь,
клиент тренера,
тренер).

Все данные пользователя
сохраняются независимо
от изменения статусов использования.

• При смене тренера
данные пользователя
не удаляются.

• Архитектура платформы
строится вокруг единого аккаунта пользователя.

• Один и тот же пользователь может одновременно использовать платформу для собственного прогресса и сопровождения клиентов.

══════════════════════════════════════════════════════════════

10. Источники полного доступа

Полный доступ к платформе может предоставляться несколькими независимыми источниками.

На текущем этапе предусмотрены:

• активный Trial;

• личная подписка пользователя;

• сопровождение тренером, имеющим действующую подписку.

Если хотя бы один источник полного доступа является активным, пользователь получает полный доступ к функциональности платформы.

Проверка источников полного доступа выполняется единым механизмом платформы и используется всеми модулями приложения.

══════════════════════════════════════════════════════════════

11. Ограниченный доступ

После прекращения действия всех источников полного доступа пользователь сохраняет доступ к просмотру своих данных.

Создание новых данных становится недоступным до появления нового источника полного доступа.

Все ранее созданные данные остаются доступны для просмотра и не удаляются по причине отсутствия полного доступа.
