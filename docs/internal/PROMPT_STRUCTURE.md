# PROMPT_STRUCTURE.md

# Стандарт формирования промптов для AI-разработчика

Версия документа: 1.0

Последнее обновление: август 2026

---

# Назначение документа

PROMPT_STRUCTURE.md определяет единый стандарт формирования задач для AI-разработчика (GitHub Copilot Agent).

Документ предназначен для ChatGPT, который формирует промпты для Copilot.

Цель документа:

- уменьшить количество ошибок;
- сократить расход контекста и кредитов;
- обеспечить стабильное качество реализации;
- сохранить единую архитектуру проекта;
- исключить самостоятельные архитектурные решения AI.

Данный документ описывает не архитектуру проекта, а правила постановки задач AI-разработчику.

---

# Общий принцип

Каждый новый промпт должен иметь одинаковую структуру.

Структура промптов не должна изменяться без отдельного архитектурного решения.

Последовательность важнее скорости.

---

# Общий порядок формирования промпта

Каждый промпт должен состоять из следующих этапов:

1. Изучение документации.
2. Анализ задачи.
3. Определение области изменений.
4. Реализация только утвержденной области.
5. Проверка результата.
6. Подготовка отчета.

---

# Изучение документации

Перед выполнением любой задачи AI обязан сначала изучить документацию.

Первым всегда читается:

docs/core/AGENTS.md

После этого читаются все документы из папки:

docs/core

в установленном порядке.

Эти документы являются обязательными для любой задачи.

Они определяют:

- правила работы AI;
- контекст проекта;
- архитектуру;
- правила разработки;
- дизайн-систему;
- рабочий процесс.

---

# Документация по текущей задаче

После изучения обязательной документации AI определяет, какие документы относятся к текущей задаче.

Например.

Работа с Home:

↓

docs/modules/HOME.md

Работа с Training:

↓

docs/modules/TRAINING.md

Работа с базой данных:

↓

docs/architecture/DATABASE_SCHEMA.md

Работа с авторизацией:

↓

docs/architecture/AUTH_ARCHITECTURE.md

Работа с пользовательскими сценариями:

↓

docs/flows/

AI должен читать только документацию, необходимую для выполнения текущей задачи.

---

# Дополнительная документация

AI имеет право самостоятельно изучить дополнительные документы проекта, если это действительно необходимо.

Например:

- проверка архитектурной зависимости;
- анализ существующей реализации;
- проверка фирменного стиля;
- поиск повторно используемых компонентов;
- проверка существующей логики;
- предотвращение дублирования;
- анализ влияния изменений на другие части проекта.

Без необходимости читать дополнительные документы запрещается.

---

# Анализ перед реализацией

До внесения любых изменений AI обязан определить:

- что именно изменяется;
- зачем выполняется изменение;
- какие файлы будут затронуты;
- затрагивается ли архитектура;
- затрагивается ли документация.

Если требования недостаточно понятны —

ОСТАНОВИТЬСЯ.

Сообщить об этом.

Запросить уточнение.

Самостоятельно принимать решения запрещено.

---

# Контроль области изменений

Каждый промпт обязан содержать два раздела.

Разрешено:

- какие файлы изменяются;
- какие папки изменяются;
- какие действия разрешены.

Запрещено:

- изменение несвязанных файлов;
- изменение бизнес-логики;
- изменение дизайна;
- изменение архитектуры;
- рефакторинг вне утвержденной области.

AI не имеет права самостоятельно расширять область задачи.

---

# Архитектурные изменения

Если во время выполнения задачи AI обнаруживает необходимость:

- изменить архитектуру;
- изменить структуру проекта;
- изменить ответственность модулей;
- изменить устройство Application Shell;

работа должна быть немедленно остановлена.

AI обязан сообщить о найденной проблеме и дождаться отдельного утверждения.

Самостоятельно принимать архитектурные решения запрещено.

---

# Независимость модулей

Каждый модуль проекта должен оставаться независимым.

Изменение одного модуля не должно требовать изменения других модулей без отдельного согласования.

Любой модуль должен иметь возможность быть полностью замененным.

---

# Стандартная структура промпта

Каждый промпт должен содержать:

1. Контекст задачи.

2. Цель.

3. Разрешенные изменения.

4. Запрещенные изменения.

5. Последовательность реализации.

6. Проверку результата.

7. Итоговый отчет.

---

# Проверка результата

После выполнения задачи AI обязан провести проверку.

При необходимости проверить:

- импорты;
- маршрутизацию;
- ссылки;
- старые пути;
- неиспользуемые файлы;
- дублирование;
- сборку проекта.

Если задача затрагивает код —

обязательно выполнить:

npm run build

если это возможно.

---

# Итоговый отчет

После выполнения задачи AI обязан предоставить отчет.

Отчет должен содержать:

- краткое описание выполненной работы;
- список измененных файлов;
- список обновленной документации;
- результаты проверки;
- затронута ли архитектура;
- следующий рекомендуемый шаг.

---

# Эффективность

Не читать документацию, не относящуюся к задаче.

Не расходовать контекст без необходимости.

Предпочитать небольшие точные промпты.

Не объединять несколько независимых задач в один большой промпт.

---

# Стиль коммуникации

Отчеты должны быть короткими и понятными.

AI должен сообщать:

- что сделано;
- почему это сделано;
- что осталось сделать.

Длинные объяснения приводятся только по запросу.

---

# Главный принцип

Главная цель разработки — не быстро выполнить задачу.

Главная цель — сохранить качество проекта.

Каждый промпт должен способствовать:

- предсказуемой реализации;
- стабильной архитектуре;
- чистому коду;
- повторному использованию решений;
- минимизации технического долга.

Последовательность важнее скорости.

Качество важнее количества.

Архитектура важнее временных решений.
