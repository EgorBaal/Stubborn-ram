# ROADMAP.md

Версия: 0.4

Последнее обновление: август 2026

---

# Назначение документа

Roadmap определяет последовательность разработки проекта.

Разработка ведется поэтапно.

Каждый следующий этап начинается только после полного завершения предыдущего.

Главный принцип разработки — последовательное развитие платформы без накопления незавершенного функционала.

- Настроены SPF.


```
Пользователь
      ↓
Анкета
      ↓
Supabase
      ↓
PostgreSQL
      ↓
Edge Function
      ↓
Resend
      ↓
Email тренеру
```

Инфраструктурный этап считается полностью завершенным.

# ЭТАП 4 — App Shell и HOME

Статус: ✅ Завершено

## Реализовано

Создан первый каркас мобильного приложения.

### Реализованы

- переход с Landing Page в приложение;
- базовая маршрутизация приложения;
- главный экран HOME;
- Header;
- Notification Section;
- Module Grid;
- BottomTabBar;
- страницы-заглушки основных разделов.

### Архитектурные решения

Приложение проектируется по принципу Mobile First.

HOME становится главным экраном приложения.

Все новые экраны должны наследовать архитектуру HOME.

BottomTabBar является глобальным переиспользуемым компонентом приложения.

На данном этапе намеренно не реализуются:

- авторизация;
- API;
- Supabase;
- база данных;
- бизнес-логика.

Основная цель этапа — создание устойчивого UI-каркаса приложения.

# Приоритет разработки

Разработка ведется строго последовательно.

Основные правила

1. Полностью завершить текущий этап.
2. Не начинать несколько крупных модулей одновременно.
3. Не оставлять незавершенный функционал.
4. После завершения этапа обновить документацию.
5. Все архитектурные решения принимаются до начала реализации.

# Цель MVP

Минимально жизнеспособная версия платформы должна позволять пользователю:

✔ зарегистрироваться;

✔ заполнить анкету;

✔ получить программу тренировок;

✔ получить план питания;

✔ отправлять отчеты;

✔ получать обратную связь тренера;

✔ просматривать историю прогресса.

После реализации этих функций MVP считается завершенным.

---

# После MVP

После завершения MVP развитие проекта продолжится в сторону полноценной платформы для нескольких тренеров.

Планируется

- поддержка нескольких тренеров;
- расширенная аналитика;
- автоматизация сопровождения;
- новые интеграции;
- развитие мобильной версии;
- коммерческая эксплуатация платформы.

---

# Правило обновления

После завершения каждого этапа необходимо обновить:

- ROADMAP.md;
- CHANGELOG.md;
- PROJECT_CONTEXT.md;
- ARCHITECTURE.md (если изменялась архитектура);
- DATABASE_SCHEMA.md (если изменялась структура данных).

Документация является частью проекта и всегда должна соответствовать фактическому состоянию кодовой базы.
