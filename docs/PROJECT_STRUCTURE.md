# Назначение основных папок

## src/assets

Назначение:

- хранение статических ресурсов интерфейса.

Ответственность:

- изображения, иконки, логотипы, шрифты, медиа-файлы.

Что может лежать внутри:

- картинки, SVG, иконки, фото, фоновые изображения.

Что не должно лежать внутри:

- бизнес-логика;
- React-компоненты;
- маршруты;
- сервисы.

---

## src/components

Назначение:

- хранение переиспользуемых UI-компонентов.

Ответственность:

- отображение интерфейса и сборка отдельных блоков страницы.

Что может лежать внутри:

- локальные компоненты модуля;
- общие UI-компоненты;
- компоненты авторизации;
- компоненты главной страницы.

Что не должно лежать внутри:

- маршруты;
- прямые запросы к Supabase;
- бизнес-логика уровня страницы;
- глобальные контексты.

---

## src/contexts

Назначение:

- хранение глобальных контекстов.

Ответственность:

- состояние, которое используется несколькими частями приложения.

Что может лежать внутри:

- AuthContext.

Что не должно лежать внутри:

- UI-стили;
- маршруты;
- бизнес-логика отдельных модулей.

---

## src/features

Назначение:

- временное место для доменной бизнес-логики и модульных заготовок.

Ответственность:

- хранение логики по функциональным областям.

Что может лежать внутри:

- подкаталоги по темам, таким как auth, chat, nutrition, questionnaire и т. п.

Что не должно лежать внутри:

- прямые стили страниц;
- общие маршруты;
- UI-компоненты без связи с логикой.

---

## src/hooks

Назначение:

- хранение пользовательских React hooks.

Ответственность:

- повторно используемая логика, связанная с состоянием и эффектами.

Что может лежать внутри:

- hooks, связанные с модулем или с общим функционалом.

Что не должно лежать внутри:

- компоненты UI;
- сервисные вызовы без необходимости;
- CSS.

---

## src/layouts

Назначение:

- хранение общей оболочки приложения.

Ответственность:

- общий shell интерфейса и общая структура страниц.

Что может лежать внутри:

- AppLayout;
- LandingLayout.

Что не должно лежать внутри:

- page-specific стили конкретного модуля;
- локальные компоненты страницы;
- бизнес-логика конкретного модуля.

---

## src/lib

Назначение:

- техническая инфраструктура интеграций.

Ответственность:

- инициализация внешних библиотек и низкоуровневых клиентов.

Что может лежать внутри:

- конфигурация Supabase клиента.

Что не должно лежать внутри:

- интерфейсные компоненты;
- маршруты;
- page-стили.

---

## src/pages

Назначение:

- хранение страниц приложения.

Ответственность:

- сборка маршрутов, размещение контента и взаимодействие с компонентами и сервисами.

Что может лежать внутри:

- Page.jsx и Page.css конкретной страницы;
- локальные компоненты страницы, если они не переиспользуются.

Что не должно лежать внутри:

- CSS другой страницы;
- импорты Page других модулей;
- общая инфраструктура приложения.

---

## src/router

Назначение:

- хранение маршрутов приложения.

Ответственность:

- маршрутизация лендинга, авторизации, анкеты и внутреннего приложения.

Что может лежать внутри:

- отдельные файлы маршрутов;
- точка сборки всех маршрутов.

Что не должно лежать внутри:

- UI-логика страниц;
- бизнес-логика модулей;
- стили.

---

## src/services

Назначение:

- хранение сервисного слоя.

Ответственность:

- взаимодействие с Supabase, внешними сервисами и бизнес-операциями.

Что может лежать внутри:

- authService;
- leadService;
- supabaseService;
- дополнительные сервисы модулей при необходимости.

Что не должно лежать внутри:

- UI-компоненты;
- CSS;
- React-контексты.

---

## src/styles

Назначение:

- хранение общих стилей и общих CSS-ресурсов.

Ответственность:

- базовые стили и общие визуальные токены.

Что может лежать внутри:

- общие CSS-файлы;
- вспомогательные стили, если они действительно общие.

Что не должно лежать внутри:

- page-specific стили отдельных модулей.

---

# Ключевые файлы проекта

## App.jsx

Назначение:

- точка входа основного React-приложения.

Отвечает за:

- запуск корневого приложения.

Используется:

- main.jsx и маршрутизацией.

Запрещено менять без необходимости:

- менять структуру приложения без анализа влияния на маршруты и shell.

---

## HomePage.jsx

Назначение:

- главная страница внутреннего приложения.

Отвечает за:

- отображение home-экранов, header, notification section и модульной сетки.

Используется:

- маршрутом внутреннего приложения.

Запрещено менять без необходимости:

- переносить логику в общие компоненты без обоснования;
- добавлять зависимости на другие страницы.

---

## ProfilePage.jsx

Назначение:

- страница профиля пользователя.

Отвечает за:

- отображение профиля и связанных данных.

Используется:

- маршрутом /app/profile.

Запрещено менять без необходимости:

- подключать CSS других страниц;
- создавать зависимость от HomePage или других модулей.

---

## AppLayout.jsx

Назначение:

- общая оболочка внутренних страниц.

Отвечает за:

- общий shell приложения и размещение контента.

Используется:

- всеми внутренними страницами приложения.

Запрещено менять без необходимости:

- вносить модульные правки в общий layout;
- менять layout ради отдельной страницы.

---

## BottomTabBar.jsx

Назначение:

- нижняя навигация приложения.

Отвечает за:

- переход между ключевыми внутренними разделами.

Используется:

- AppLayout и внутренними страницами через общий shell.

Запрещено менять без необходимости:

- адаптировать навигацию под один модуль без глобальной причины.

---

## router.jsx

Назначение:

- главный маршрутизатор приложения.

Отвечает за:

- сборку маршрутов приложения.

Используется:

- App.jsx.

Запрещено менять без необходимости:

- добавлять новые маршруты без обновления соответствующих route-файлов.

---

## AuthContext.jsx

Назначение:

- хранение состояния авторизации.

Отвечает за:

- доступ к сессии пользователя и её состоянию.

Используется:

- защищёнными страницами и компонентами авторизации.

Запрещено менять без необходимости:

- внедрять бизнес-логику модулей в контекст.

---

## App

Ответственность:

- точка запуска приложения.

Допустимые зависимости:

- Router.

Запрещённые зависимости:

- прямое использование page-specific логики без маршрутизации.

---

## Router

Ответственность:

- распределение маршрутов по лендингу, авторизации, анкете и внутреннему приложению.

Допустимые зависимости:

- Layout;
- Pages.

Запрещённые зависимости:

- прямые зависимости от UI-компонентов конкретной страницы.

---

## Layout

Ответственность:

- общая оболочка приложения и контейнер для контента.

Допустимые зависимости:

- Pages;
- общие компоненты.

Запрещённые зависимости:

- модульная логика конкретной страницы;
- page-specific CSS одного модуля.

---

## Pages

Ответственность:

- представление конкретной страницы и координация её контента.

Допустимые зависимости:

- Components;
- Hooks;
- Services.

Запрещённые зависимости:

- импорт другой Page;
- использование CSS другой страницы.

---

## Components

Ответственность:

- отображение интерфейса и составных частей страницы.

Допустимые зависимости:

- UI-компоненты;
- Hooks.

Запрещённые зависимости:

- импорт Page;
- прямой доступ к маршрутам уровня приложения.

---

## Hooks

Ответственность:

- повторно используемая логика состояния и эффектов.

Допустимые зависимости:

- Services.

Запрещённые зависимости:

- прямые зависимости от UI-компонентов страницы.

---

## Services

Ответственность:

- взаимодействие с внешними системами.

Допустимые зависимости:

- другие Services;
- низкоуровневые библиотеки и клиенты.

Запрещённые зависимости:

- UI-компоненты;
- Page-компоненты;
- CSS.

---

## Supabase

Ответственность:

- хранение данных и серверная интеграция.

Допустимые зависимости:

- только через Services.

Запрещённые зависимости:

- прямой доступ из UI или Pages.

---

# Правила зависимостей

| Слой      | Может зависеть от              | Запрещённые зависимости                                                             |
| --------- | ------------------------------ | ----------------------------------------------------------------------------------- |
| Page      | Components, Hooks, Services    | Page → Page, Page → CSS другой страницы, Page → AppLayout как локальное исправление |
| Component | UI, Hooks                      | Component → Page, Component → Router                                                |
| Hook      | Services                       | Hook → Router, Hook → Page                                                          |
| Service   | lib, Supabase, другие Services | Service → Component, Service → Page                                                 |
| Layout    | Router, Shared UI, Pages       | Layout → Page-specific логика, Layout → CSS одного модуля                           |
| Router    | Layout, Pages                  | Router → Component уровня страницы                                                  |

## Page может использовать

- Components;
- Hooks;
- Services.

## Page не может

- импортировать другую Page;
- использовать CSS другой страницы;
- изменять общую оболочку ради одного модуля.

---

## Component может использовать

- другие UI-компоненты;
- Hooks.

## Component не может

- импортировать Page;
- напрямую вызывать общую инфраструктуру как модульное решение.

---

## Hooks могут использовать

- Services.

## Hooks не должны

- зависеть от UI-структуры страницы;
- хранить page-specific стили.

---

## Services не должны зависеть от UI

Services должны работать только с данными и внешними интеграциями.

---

# Алгоритм разработки новой задачи

При любой новой задаче разработчик обязан:

1. определить модуль;
2. определить страницу;
3. проверить локальные компоненты;
4. изменять сначала Page;
5. затем локальные Components;
6. только после этого Hooks;
7. только затем Services.

AppLayout менять только если проблему невозможно решить локально.

BottomTabBar менять только если изменение относится ко всему приложению.

Router менять только если добавляется новый маршрут.
