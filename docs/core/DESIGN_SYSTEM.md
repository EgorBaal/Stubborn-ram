# Дизайн-система проекта Stubborn Ram

Версия: 0.3

Последнее обновление: август 2026

---

# Назначение документа

Данный документ описывает все правила оформления интерфейса проекта.

Его цель — сохранить единый стиль приложения независимо от количества экранов и компонентов.

Любой новый экран должен соответствовать этим правилам.

---

# Общая концепция

Stubborn Ram — это не просто сайт.

Это веб-приложение для сопровождения клиентов.

Интерфейс должен восприниматься как современное мобильное приложение, которым удобно пользоваться каждый день.

Основные качества дизайна:

- минимализм;
- строгость;
- современность;
- удобство;
- скорость восприятия;
- отсутствие визуального шума.

---

# Основной стиль

- Темная тема.
- Большое количество свободного пространства.
- Минимум цветов.
- Крупные карточки.
- Плавные анимации.
- Хорошая читаемость.

# Interaction Policy

Этот раздел является единым местом хранения всех правил взаимодействия интерфейса.

В будущем новые архитектурные правила взаимодействия добавляются именно сюда.

## Hover Policy

Все новые hover-эффекты в проекте должны объявляться только внутри

```
@media (hover: hover) and (pointer: fine)
```

Это правило обязательно для всех новых модулей и новых интерфейсных состояний.

На устройствах с сенсорным вводом hover-эффекты по умолчанию не используются.

Если модулю действительно требуется hover-поведение, оно должно быть задано
локально внутри его собственного CSS и не должно выходить за пределы этого
модуля.

---

## Touch Policy

Будущий стандарт для правил работы интерфейса при касании на сенсорных
устройствах.

## Focus Policy

Будущий стандарт для правил отображения и поведения focus-состояний.

## Selection Policy

Будущий стандарт для правил выделения текста и элементов интерфейса.

## Loading Policy

Будущий стандарт для правил отображения состояний загрузки.

---

# Поля ввода

Используются одинаковые стили.

Одинаковые:

- скругления;
- высота;
- внутренние отступы;
- размер текста.

---

# Единые компоненты интерфейса

При разработке новых экранов рекомендуется использовать единый набор компонентов.

Основные компоненты проекта:

- Button
- Input
- Card
- Modal
- PageHeader
- Section
- Toast (в будущем)

Создание нескольких вариантов одного и того же компонента допускается только при наличии объективной необходимости.

---

# Карточки

Все карточки должны выглядеть одинаково.

Используются:

- темный фон;
- большие внутренние отступы;
- крупные скругления.

Без тяжелых теней.

Карточка должна восприниматься как отдельный логический блок.

---

# Анимации

Все анимации плавные.

Продолжительность:

200–350 ms

Использовать мягкое появление элементов.

Не использовать резкие эффекты.

---

# Reveal-анимации

Для появления блоков используется единый стиль Reveal-анимаций.

Элементы появляются плавно при попадании в область просмотра.

Не использовать различные типы анимаций без необходимости.

---

# Иконки

Использовать минималистичные иконки.

Один стиль на весь проект.

---

# Изображения

Все изображения высокого качества.

Не использовать растянутые изображения.

Не использовать разные стили обработки фотографий.

Все фотографии должны иметь одинаковый визуальный стиль.

---

# Сравнение результатов

Для фотографий "До / После" используется единый компонент сравнения.

Все изображения должны иметь одинаковые пропорции и качество.

---

---

# Навигация

Навигация должна быть максимально простой.

Пользователь всегда должен понимать:

где он находится;

что делать дальше;

как вернуться назад.

---

# Личные кабинеты

Все экраны личного кабинета клиента и кабинета тренера должны использовать единые принципы оформления.

Не допускается создание отдельных дизайн-стилей для разных разделов платформы.

Все страницы должны восприниматься как части одного приложения.

---

# Mobile First

Все новые экраны сначала проектируются для телефона.

После этого адаптируются под планшет и ПК.

---

# Адаптивность

Все новые компоненты должны корректно работать:

- на мобильных устройствах;
- на планшетах;
- на ПК.

Не допускается создание отдельных дизайнов для разных платформ без необходимости.

---

# Чего нельзя делать

❌ Пестрые цвета.

❌ Мелкий текст.

❌ Слишком плотное расположение элементов.

❌ Огромные блоки текста.

❌ Разные стили кнопок.

❌ Разные радиусы скругления.

❌ Разные размеры полей ввода.

❌ Разные стили карточек.

❌ Использовать более одного акцентного цвета.

---

# Основной принцип дизайна

Каждый новый экран должен выглядеть так, будто он существовал в проекте с самого начала.

Пользователь не должен замечать разницу между старыми и новыми разделами.

Визуальная целостность проекта является одним из главных требований.

---

# Философия интерфейса

Интерфейс Stubborn Ram должен вызывать ощущение спокойствия, надежности и профессионализма.

Дизайн не должен отвлекать пользователя.

Главная задача интерфейса — быстро донести информацию и помочь пользователю выполнять действия без лишних усилий.

---

# Будущее развитие

По мере развития проекта дизайн-система может расширяться новыми компонентами и паттернами.

Любые новые элементы интерфейса должны сначала быть описаны в данном документе, после чего использоваться в проекте повторно.

Это позволяет сохранить единый визуальный стиль приложения по мере роста функциональности.
