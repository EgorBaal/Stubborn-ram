# ARCHITECTURE_LAYOUT

## 1. Назначение Layout системы

Layout система приложения определяет единый каркас внутренних App-экранов и границы ответственности между слоями.

Ее задачи:

- обеспечить предсказуемое размещение контента и нижней панели;
- обеспечить единые правила safe-area и scroll-контекста для App-маршрутов;
- исключить дублирование управления геометрией TabBar;
- сделать каждое изменение TabBar одноточечным и понятным.

Layout система не должна переносить ответственность между слоями ради быстрых локальных правок.

---

## 2. Общая схема архитектуры

```text
App
-> Router
-> AppLayout
-> app-shell
-> app-page
-> app-scroll
-> app-tabbar
-> BottomTabBar
```

Примечание:

- `BottomTabBar` рендерится внутри `app-tabbar`;
- модульные страницы рендерятся через `Outlet` внутри `app-scroll`;
- TabBar существует в одном экземпляре для всех App-маршрутов.

---

## 3. Ответственность каждого слоя

### AppLayout

Отвечает:

- за сборку App-каркаса (контентная зона + зона нижней панели);
- за контракт взаимодействия слоев Layout;
- за подключение общего `BottomTabBar` для всех App-страниц.

Не отвечает:

- за внутреннюю форму и внутреннюю геометрию `BottomTabBar`;
- за локальные стили модульных страниц;
- за компенсацию под TabBar в нескольких слоях одновременно.

Имеет право менять:

- правила каркаса App-уровня;
- распределение ответственности между `app-shell`, `app-page`, `app-scroll`, `app-tabbar` (в рамках контракта);
- только внешнюю оболочку размещения TabBar.

Запрещено менять:

- внутренние параметры `BottomTabBar` (форма, внутренние размеры, индикатор);
- модульные страницы ради исправления глобальной геометрии TabBar.

### app-shell

Роль:

- корневой контейнер App-оболочки;
- задает рабочую экранную область и shell-отступы;
- обеспечивает общую рамку для `app-page` и `app-tabbar`.

### app-page

Ответственность:

- контентная колонка приложения;
- ограничение ширины контентной зоны;
- визуальный контейнер страницы (например, скругление и clipping контентной области).

Не отвечает за:

- положение TabBar;
- резерв пространства под TabBar.

### app-scroll

Единственная задача:

- управлять scroll-контекстом и резервом пространства под фиксированную нижнюю панель.

Правило:

- только `app-scroll` владеет параметром `reserved-space-under-tabbar`.

### app-tabbar

Отвечает только за внешнюю геометрию TabBar:

- положение по X и Y;
- расстояние до нижнего края экрана;
- интеграцию safe-area для внешнего размещения панели;
- ширину и максимальную ширину контейнера панели;
- z-index и слой поверх контента.

Не отвечает за:

- внутреннюю форму панели;
- внутреннюю высоту, padding, сетку и индикатор.

### BottomTabBar

Отвечает только за внутреннюю геометрию и UI панели:

- форма панели;
- внутренняя визуальная высота;
- внутренние padding;
- внутренний grid;
- внутренние элементы (`item`, `icon`, `label`, `indicator`, `chat button`);
- внутренние брейкпоинты компонента.

Не отвечает за:

- экранное позиционирование панели;
- резерв контента под панель;
- глобальные safe-area правила Layout-слоя.

## 4. Владельцы параметров (single owner)

Каждый параметр имеет ровно одного владельца.

| Параметр                                       | Единственный владелец |
| ---------------------------------------------- | --------------------- |
| `bottom-offset`                                | `app-tabbar`          |
| `tabbar-x-position`                            | `app-tabbar`          |
| `tabbar-width`                                 | `app-tabbar`          |
| `tabbar-max-width`                             | `app-tabbar`          |
| `safe-area-policy` (внешнее размещение панели) | `app-tabbar`          |
| `tabbar-layer-z-index`                         | `app-tabbar`          |
| `reserved-space-under-tabbar`                  | `app-scroll`          |
| `app-scroll-behavior`                          | `app-scroll`          |
| `app-content-max-width`                        | `app-page`            |
| `app-shell-side-gap`                           | `app-shell`           |
| `tabbar-visual-height`                         | `BottomTabBar`        |
| `tabbar-radius`                                | `BottomTabBar`        |
| `tabbar-padding`                               | `BottomTabBar`        |
| `tabbar-grid`                                  | `BottomTabBar`        |
| `indicator` (высота, форма, анимация)          | `BottomTabBar`        |
| `chat-button` (размер, форма)                  | `BottomTabBar`        |
| `tab-item-min-height`                          | `BottomTabBar`        |
| `icon-size`                                    | `BottomTabBar`        |
| `label-size`                                   | `BottomTabBar`        |

Правило валидации:

- если один параметр редактируется в двух разных слоях, это архитектурная ошибка.

---

## 5. Золотые правила проекта

1. Если требуется изменить положение TabBar, изменяется только `app-tabbar`.
2. Если требуется изменить форму или внутреннюю геометрию TabBar, изменяется только `BottomTabBar`.
3. Если требуется изменить резерв под TabBar, изменяется только `app-scroll`.
4. Нельзя компенсировать TabBar одновременно в нескольких слоях.
5. Нельзя менять модульные страницы для исправления глобальной геометрии Layout.
6. **Запрещено менять параметр вне его владельца, даже если это кажется более быстрым решением.**
7. Предсказуемость важнее компактности: меньше магии, больше явных контрактов.

---

## 6. Как вносить изменения

### Сценарий A: нужно поднять/опустить TabBar

- редактируется только `app-tabbar`;
- не изменяются внутренние стили `BottomTabBar`;
- не изменяются модульные страницы.

### Сценарий B: нужно изменить форму панели

- редактируется только `BottomTabBar` (`BottomTabBar.css`);
- не изменяется `app-tabbar` позиционирование.

### Сценарий C: нужно изменить резерв под панель

- редактируется только `app-scroll`;
- не добавляются дополнительные компенсации в `app-page`, `app-shell`, модулях.

### Сценарий D: требуется правка сразу в нескольких слоях

Перед изменением обязательно:

1. письменно зафиксировать, почему один слой не покрывает задачу;
2. показать, почему мультислойная правка не нарушает контракт;
3. описать rollback-план и ручные проверки.

Без этого правка считается нарушением архитектурного стандарта.

---

## 7. Архитектурные анти-паттерны

Запрещено:

- один параметр имеет двух владельцев;
- компенсация TabBar в нескольких местах одновременно;
- изменение модульной страницы ради исправления Layout;
- изменение `BottomTabBar` ради экранного позиционирования панели;
- изменение `Layout` ради внутренней формы панели;
- дублирование токенов одного и того же параметра в разных слоях;
- смешивание внешней и внутренней геометрии в одном слое.

---

## 8. Чек-лист перед merge

1. Для каждого измененного параметра указан единственный владелец.
2. Нет дополнительных компенсаций под TabBar вне `app-scroll`.
3. Нет правок модульных страниц для решения глобальной Layout-задачи.
4. На всех App-маршрутах геометрия предсказуема и повторяема.
5. Документ `docs/ARCHITECTURE_LAYOUT.md` остается источником архитектурной истины.
